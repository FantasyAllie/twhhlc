- Menu-opened Sheets/Dialogs render in place of the home screen via the takeover slot in ui/sheet.tsx (armSheetTakeover before opening); why: one consistent in-page panel pattern instead of popups.
- Leaderboard menu visibility uses the shared leaderboard-access helper against assigned departments, not the active department view; why: Housekeeping assignment grants access consistently across menu layouts while database policies enforce data access.
- Nightly fallback exports run entirely in PostgreSQL through restricted functions and one DST-aware pg_cron job; why: exports must work without an open device, preserve each existing hotel/day/kind report, and match the end-of-shift formats and unchanged-counter exclusions.
- On iPhone, More and primary tab screens use the takeover slot with hideClose; screen height is measured against the floating tab bar's top edge so navigation stays available without covering content.
- Room item selectors use hotel-scoped editable settings and current selections on rooms, saved through an authenticated per-item database function; completion snapshots are saved atomically with done through a database function; why: optional persistent selections without pop-ups while preserving immutable exported records.
- Marking a room done closes the room view by collapsing the open room slot and clearing the status view inside the collapse callback; why: marking done ends the visit to that room, and clearing the status view before the collapse would flash the room hub mid-animation.
- Room action tabs live once in a stable room frame, with child views portalled into its body without nested framing; only opening/closing the room animates, so switching tabs cannot move navigation or briefly collapse the room.
- Home room filter options share the FilterOption button component with aria-pressed selection; why: consistent platform styling and accessible multi-selection without checkbox squares.
- Department-specific bottom tabs are filtered by the shared department-tabs helper against assigned departments; why: avoid duplicating a department already accessed through Home as navigation grows.
- Overlay panels and menu primitives expose shared OS styling markers while inline screens stay unframed; why: consistent glass or Material treatment without changing room tiles.
- iOS shadow clearance belongs to shared Sheet/Dialog scroll surfaces: growing room bodies do not clip, while bounded lists reserve shadow gutters and tab-bar clearance; why: avoid cut-off glass shadows without changing tiles or unlocking background scrolling.
- Home pull-to-refresh uses native non-passive touch listeners only on mobile Home at scroll-top and awaits active query invalidation; why: Safari/Chrome cancel pointer gestures when scrolling, and other screens must retain their own scroll behaviour.

- Mobile breakpoint is 1024px (use-mobile.tsx MOBILE_BREAKPOINT, sheet.tsx isPhone); tablets keep the mobile top bar but use the docked menu instead of bottom tabs; why: tablet navigation stays in one permanently visible place.
- Room tab bodies: the room summary stays visible until the tab's inline sheet has mounted (roomSummaryHidden + MutationObserver in app.tsx); why: a slow first render must not leave an empty gap that pulls the tiles up.
- Takeover arm window is 5s (armSheetTakeover in ui/sheet.tsx); why: a real iPhone's first render of a heavy panel can exceed a short window, and a missed arm falls back to a slide-up sheet.
- Centred-popup styling (IOS_CENTRED_POPUP) goes in SheetContent's popupClassName, never className, whenever the sheet can be opened from the menu (takeover-armed); iOS room-hub logging (maintenance, lost property) uses centred compose-only popups so logging from a room does not replace the screen; top-1/2/-translate-y-1/2 classes would displace inline takeover panels out of view on iPhone (the Departments picker bug).
- Department message groups use the shared message-groups helper and group_key, with hotel-scoped database policies enforcing assigned groups plus shared Reception; legacy thread is retained only for historical log compatibility; why: group access and sender identity must be enforced beyond the menu.
- Reception room comments use the shared Housekeeping destination and a narrow own-room-message policy for reception-only senders; why: cross-department room handoffs must not expose the full Housekeeping chat.
- The iPhone app manages users through POST /api/users (src/routes/api.users.ts), which only wraps the same auth.functions server functions as the Users dialog using the caller's Bearer token; why: the admin key stays on the server and permission rules live in one place.
- Morning sheet imports are read by the AI gateway in a server function, stored as one pending row per hotel, and applied only through the resolve_morning_sheet database function; why: Housekeeping must confirm before a document overwrites live room statuses, and the update must be atomic.
- Developer-only test hotels (hotels.developer_only) are hidden by the hotels read policy, can_access_hotel, membership/active-hotel triggers and the hotel list server functions; why: testing must never surface to, notify, or mix stats with real staff.
- On tablets (768-1023px) the menu is a fixed right sidebar with Home above AppMenuRows and no tab bar or spacer; the header cancels the tablet wrapper's top padding, and dock height uses the platform-specific topbar token; why: navigation stays available without header overlap or unused bottom space.
- Home floor pills use the department picker's segmented-control treatment at every size (rounded track, compact pills, selected filled solid); All rooms on tablet/desktop, phones keep one sideways-scrolling track that hugs its pills; rooms share one auto-fill grid and row-slot calculation.
- Central hotel floors have immutable cupboard keys; assignments save atomically and renames sync rooms and exports; why: one list without losing counts.
- Room Management loads with the app, not lazily; why: More must hand off immediately without a Home gap on slow first opens.
