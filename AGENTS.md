- Menu-opened Sheets/Dialogs render in place of the home screen via the takeover slot in ui/sheet.tsx (armSheetTakeover before opening); why: one consistent in-page panel pattern instead of popups.
- Leaderboard menu visibility uses the shared leaderboard-access helper against assigned departments, not the active department view; why: Housekeeping assignment grants access consistently across menu layouts while database policies enforce data access.
- On iPhone, More and primary tab screens use the takeover slot with hideClose; screen height is measured against the floating tab bar's top edge so navigation stays available without covering content.
- Room item selectors use hotel-scoped editable settings and current selections on rooms, saved through an authenticated per-item database function; completion snapshots are saved atomically with done through a database function; why: optional persistent selections without pop-ups while preserving immutable exported records.
- Marking a room done closes the room view by collapsing the open room slot and clearing the status view inside the collapse callback; why: marking done ends the visit to that room, and clearing the status view before the collapse would flash the room hub mid-animation.
- Room action tabs live once in a stable room frame, with child views portalled into its body without nested framing; only opening/closing the room animates, so switching tabs cannot move navigation or briefly collapse the room.
- Home room filter options share the FilterOption button component with aria-pressed selection; why: consistent platform styling and accessible multi-selection without checkbox squares.
- Department-specific bottom tabs are filtered by the shared department-tabs helper against assigned departments; why: avoid duplicating a department already accessed through Home as navigation grows.
- Overlay panels and menu primitives expose shared OS styling markers while inline screens stay unframed; why: consistent glass or Material treatment without changing room tiles.
- iOS shadow clearance belongs to shared Sheet/Dialog scroll surfaces: growing room bodies do not clip, while bounded lists reserve shadow gutters and tab-bar clearance; why: avoid cut-off glass shadows without changing tiles or unlocking background scrolling.
- Home pull-to-refresh uses native non-passive touch listeners only on mobile Home at scroll-top and awaits active query invalidation; why: Safari/Chrome cancel pointer gestures when scrolling, and other screens must retain their own scroll behaviour.

- Mobile breakpoint is 1024px (use-mobile.tsx MOBILE_BREAKPOINT, sheet.tsx isPhone); tablets get the mobile layout: bottom tab bar, mobile top bar, no menu button. Aligns with the lg: utilities used for the tab bar.
- Room tab bodies: the room summary stays visible until the tab's inline sheet has mounted (roomSummaryHidden + MutationObserver in app.tsx); why: a slow first render must not leave an empty gap that pulls the tiles up.
- Takeover arm window is 5s (armSheetTakeover in ui/sheet.tsx); why: a real iPhone's first render of a heavy panel can exceed a short window, and a missed arm falls back to a slide-up sheet.
- iOS room-hub logging (maintenance, lost property) opens centred compose-only popups (IOS_CENTRED_POPUP class + composeOnly/contentClassName props on the sheets); why: logging from a room should not replace the screen with the full log windows.
- Centred-popup styling (IOS_CENTRED_POPUP) goes in SheetContent's popupClassName, never className, whenever the sheet can be opened from the menu (takeover-armed); why: top-1/2/-translate-y-1/2 classes displace inline takeover panels out of view on iPhone (the Departments picker bug).
